The evidence behind the grades

Every grade on this site is built from individual findings. Each row in these files is one problem in one insurer's published listing, exactly as published. Every record-level row carries the fingerprint (SHA-256 hash) of the archived file it came from and the position of the record inside it, so a finding can be traced to one entry in one dated file. The out-of-area files are the exception, because they are published as per-plan totals rather than record rows, so they carry a plan ID instead.

How to resolve a fingerprint. Look the hash up in source_manifest.csv.gz above. That gives you the exact web address we fetched, the timestamp, and the ETag and Last-Modified the insurer's own server reported. If the insurer has not regenerated the file since, fetching that address and hashing it yourself reproduces the same SHA-256. If it has been regenerated, which is expected because these files update monthly, the ETag and timestamp still pin what was served on the day we read it. We keep the archived bytes and will send the file for any hash on request, at {{ contact }}. We do not republish the archive in bulk, because those files carry named providers' addresses and phone numbers, and this project identifies providers by their federal ID rather than by name.

Provider details in these files are quoted from the insurer's published directory. No claim is made about the provider. Listed clinicians are often unaware of how they appear in payer directories.

One finding type, out-of-area listings, produces hundreds of millions of rows, so for it we publish per-plan totals plus a 250,000-row random sample. Two more finding types, old update dates and shared phone numbers, also exceed 250,000 rows and ship as random samples of that size. Every other finding type ships complete, including placeholder values, which exceeds 250,000 rows but is small enough to publish whole. Complete sets are reproducible; see below.

Prefer to explore without downloading? Open the scores file in Datasette Lite, a free tool that runs in your browser, so you can poke at the data without installing anything.

What the columns mean

In plan_county_scores, one row is one plan in one county in one scope (mental health or all providers).

ColumnWhat it means
scoreThe final 0 to 100 number for that row.
gradeThe letter grade for that score.
nHow many providers the plan lists in that county.
thin_rosterMarks lists under 10 providers, which get no grade.
out_of_area_rateThe share of the plan's listings with no listed address in or near its counties.
score_uniformThe score re-run with every check weighted equally, a check that our chosen weights aren't driving the grade.
low_sampleTrue for a county list of 10 to 29 providers. Graded, but on thin evidence.
numeric_suppressedTrue when the list is small enough that the flag-rate confidence interval spans more than 25 points. Do not quote the score for these rows. The letter grade is still meaningful; the exact number is not. If you build anything on this data, filter on this column.

In the evidence files, one row is one problem in one listing.

ColumnWhat it means
metricWhich check produced the row.
source_sha256The fingerprint of the insurer file the row came from. Look it up in source_manifest.csv.gz to see which address it was fetched from and when.
record_idxThe entry's position inside that file.
observedThe values exactly as published.

Check our work, or rebuild everything

This site is produced by open-source software from public government data. The code lives at github.com/ghost-network-watch. The inputs are all public: CMS's directory-address file for every marketplace insurer, the insurers' own published directory files, the federal NPPES provider registry, and CMS's plan and service-area filings.

The pipeline runs one command per stage: fetch the files, parse them, run the checks, compute the scores, build this site. The repository's documentation walks through each stage. Running a full month costs a few hours of computer time and produces every row summarized above, including the complete sets we sample here.
